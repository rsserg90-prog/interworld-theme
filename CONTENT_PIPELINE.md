# Как перевести блог в энциклопедию

Этот документ описывает подготовку материалов из архива «Блог Энмеркара 2008–2026». Он дополняет [SITE_BRIEF.md](SITE_BRIEF.md); команды и детали запуска находятся в [README конвейера](tools/content-pipeline/README.md).

## Что уже извлечено

- **1 273 статьи**, примерно **941 тысяча слов**.
- Тексты разделены по оглавлению EPUB, а не по произвольному размеру файла.
- **1 198 ссылок из оглавления с якорем точно совпали с заголовками статей** внутри EPUB.
- Сохранены заголовки, очищенный текст, ссылки на другие статьи и точное место статьи в архиве.
- В статьях нет вложенных изображений. Найдена одна обложка всего EPUB.
- В выгрузке есть названия 11 прежних рубрик, но нет достоверной таблицы «статья → рубрика». Эти названия нельзя без проверки приписать всем статьям.
- Дата публикации отдельной статьи в EPUB не обнаружена. Служебные даты EPUB не используются как даты статей.

Подробная сводка и список материалов лежат вне Git-репозитория в `D:\Проект Interworld\content-work\`:

- `EPUB_AUDIT.md` — сводка о файле;
- `articles_inventory.csv` — названия и размеры статей для просмотра в Excel;
- `source_articles.jsonl` — полный локальный корпус для скриптов;
- `epub_legacy_categories.json` — рубрики из оглавления и предупреждение об отсутствии их связей со статьями;
- `topic_proposals.csv` — предлагаемые темы для просмотра в Excel (пока ни одна не утверждена);
- `blog_cover.jpeg` — обложка архива.

## Три разных понятия, которые нельзя смешивать

1. **Статья источника** — самостоятельный текст из блога. Для неё подходит `iw_article`. Исходный текст сохраняется; ИИ не переписывает его.
2. **Тема** — широкая метка для навигации и поиска, например «Архонты», «Магия» или «Межмирье». Это `iw_topic`; у одной статьи может быть несколько тем.
3. **Сущность энциклопедии** — отдельная каноническая страница о конкретном существе, месте, эфире, божестве, термине или личности. Её нельзя создавать заново при каждом упоминании в статье.

Таблица структуры подтверждает, что Фейри должны иметь отдельный тип страницы. Сейчас такого типа в теме нет, поэтому скрипт только отмечает фейри как кандидатов в заметках редактора; страницы Фейри автоматически не создаются.

## Какие темы предлагаются

`tools/content-pipeline/topics.json` содержит начальный список тем. Все они пока помечены `approved: false`: это предложения для первой пробы, а не уже утверждённая рубрикация. Шесть названных вами тем отмечены `recommended_for_pilot: true`; в WordPress они не появятся, пока вы отдельно их не утвердите. Тот же список в удобном для Excel виде — `D:\Проект Interworld\content-work\topic_proposals.csv`.

| Источник списка | Примеры |
|---|---|
| Прямо названы заказчиком | Межмирье, Эфиры, Фейри, Демоны, Архонты, Боги |
| Есть в дереве из Excel | Эоны, Существа, Пространства, Посмертие, Символы и атрибуты |
| Найдены среди старых рубрик EPUB | Огам, Гностицизм, Гоэтика, Личное, Магия, Межмирье, Миф, Наблюдения, Путь, Руны, Теургия |

Старую рубрику «Oгам» в EPUB нужно проверить: первая буква там латинская `O`, а в обычном русском написании ожидается кириллическая «О». Список тем в настройке приведён к кириллическому написанию, а исходный вариант сохранён отдельно.

Для первой пробы я бы начал с шести тем, которые вы уже назвали: Межмирье, Эфиры, Фейри, Демоны, Архонты, Боги. Это рекомендация для пилота, а не окончательное решение: в `topics.json` все темы пока `approved: false`. Более узкие темы можно добавить позже, если они действительно улучшат поиск и навигацию. Тип сущности выбирается отдельно от темы: например, Демоны могут быть темой статьи, а конкретный демон — карточкой существа.

## Что делает ИИ и что проверяет человек

Для каждой статьи ИИ может предложить краткое описание, 1–4 темы, возможные отдельные сущности, важные утверждения, внутренние связи и список редакторских предупреждений. У предложений должны быть точные цитаты из статьи. Скрипт проверяет совпадение цитаты с исходным текстом.

Авторские трактовки из блога остаются позициями источника. ИИ не объявляет их независимо подтверждёнными фактами и не заменяет проверку внешней истории или мифологии. Если предложение по теме, сущности, цитате или источнику сомнительное, материал остаётся на ручной проверке.

Редактор проверяет дубли по существующим страницам, решает, какая карточка является основной, уточняет связи и источники. Только затем выбранные темы могут быть применены в WordPress. Автоматической публикации нет.

## Картинки и права

В статьях этого EPUB изображения не найдены; есть только обложка. Поэтому импортёр не ставит изображение каждой статье. Обложку можно привязать к записи-источнику после проверки права на использование. Иллюстрации для отдельных существ и мест нужно подбирать отдельно и хранить вместе с подписью, автором/правообладателем, основанием использования и alt-текстом.

## Что потребуется перед реальным запуском

- Утвердить основной список тем после просмотра пробного набора.
- Для ИИ-обработки задать отдельный API-ключ OpenAI Platform в локальной переменной окружения. Запросы передают текст статьи во внешний API и могут тарифицироваться; поэтому сначала разумно обработать около 20 статей.
- Для записи черновиков задать WordPress Application Password пользователя, которому разрешено создавать статьи. Эти данные не следует передавать в чат или класть в Git.
- Указать исходный адрес блога, если он известен и должен показываться как кликабельная ссылка. Из EPUB такой адрес для каждой статьи получить не удалось.
- Для книг отдельно сохранить название, том, главу, страницы, ссылку/издание и права на текст и иллюстрации. Книги не включены в текущую автоматическую обработку.

До готовности этих данных можно просматривать список статей и извлечённые тексты. Скрипты по умолчанию ничего не отправляют в API и не изменяют WordPress.
